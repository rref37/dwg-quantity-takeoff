# 各专业适配

三方取证法本身与专业无关——都是从 DWG 数图块或符号。区别只在图层命名、块名习惯，以及哪里有更权威的数量来源（明细表）。通用第一步是：用方法③渲染该专业图例，拿到“符号↔名称”对照，再开始数。

> 重要：很多专业图里都有现成的明细表或材料表（门窗表、配筋表、设备材料表、物料表）。这些表是设计师自己汇总的，优先查表；表里数量栏若写“详平面/见图”，才回头数图块。

> 本文用通用情形和示意名称说明判断方法。它不是某套真实图纸的实测报告，也不提供可以引用的工程量。文中的块名、规格、图层和面积关系都是示例：能帮助认图，不能当成已经清点过的数据。不要把示例数字写进成果。

## 电气

- 图层示例：`EM-强电`（插座）、`EM-弱电`（数据/电视/电话）、`EM-开关`、`EQUIP-安防`（摄像机）、`EQUIP-应急`（疏散灯）、`RC-LIGHT` / `EQUIP-照明`（灯具）、`EQUIP-箱柜`（配电箱）、`EQUIP-消防`、`E-EQPM-动力`。先用 `02_count.py` 看这张图实际用了哪套名字。
- 灯具常是匿名块，靠方法②指纹加方法③渲染图例。
- 配电箱和回路数看系统图。系统图通常按栋或按系统分开，比一张共用的平面更适合分栋。
- 线缆规格看系统图标注（例如 WDZB1-BYJ 一类写法）。长度图上常常不画，只能估算。

## 给排水

> 给排水和电气差别最大，不能把电气的“按块名计数”直接套过来。下面带 ⚡ 的是给排水里反复出现的通用情形。

- **图层通常比块名可靠。** 块名可能是无意义字符串。示例（不要到图里搜索这些字面）：`as1df2`、`qwer99`。`BlockTableRecord` 这时认不出设备类型。先看图层直方图，再决定用哪套分类：
  - 美标 `P-` 体系示例：`P-WatS`（给水）、`P-WatS-Anno`（给水标注或水表点位）、`P-Hydt` / `P-Hydt-Boxx`（消火栓或消火栓箱）、`P-Sprl-Anno`（喷淋）、`P-RFDR`（雨水斗）、`P-STRM`（雨水）、`P-Soil-Anno`（污水）、`P-Wast-Anno`（废水）、`P-Strt`（排水）。
  - 中文图层也常见：`VALVE_废水`、`EQUIP_污水`，以及按系统分开的 `PIPE-给水` / `PIPE-污水` / `PIPE-雨水` / `PIPE-消防` / `PIPE-喷淋`。
  - 老式天正图也可能是 `W-` / `D-` / `F-`，或“管 / 阀 / 洁具”。先 `02_count` 认体系，不要假定每张图都用同一套名字。
- 常见计数对象：洁具（坐便、洗手盆、地漏、拖布池）、阀门（闸阀、蝶阀、止回、减压、截止、角阀）、水表、管件（弯头、三通、变径）、消火栓箱、喷头、雨水斗、清扫口、检查口、存水弯、通气帽、灭火器、水泵接合器。

### ⚡ 喷头可能只出现在系统示意里

渲染喷淋相关图层（名称类似 `P-Sprl-Main`、`P-Sprl-Sprl`、`P-Sprl-Anno`）之后，平面上可能只有报警阀、系统块和少量图例，没有铺满房间的喷头。这时喷头数量要查喷淋系统图或消防设计说明（按保护面积和喷头间距计算），不要把示意块当成喷头数。报数前先渲染，确认平面到底有没有布点。

### ⚡ 同一层常被画成多套系统分版

一层平面常复制成给水图、排水图、消防图、喷淋图。每张是同一底图的副本，只突出本系统。同一个地漏、立管或消火栓会在好几张图上各出现一次，全数会成倍增加。电气图通常没有这个副本。

- 判定：按 X 坐标把块分成并排的几列，逐列统计每个图层的块数。两列逐图层数字几乎一致，就是互为副本。
- 去重：只保留最完整的一列。相邻列数量接近、另一列残缺时，通常只留完整列。
- 这和图框窗口去重不同。窗口去重排除的是图例和详图；这里排除的是整张平面的系统分版。

### ⚡ 缩写块若刚好等于副本套数，多半不是平面设备

阀门和设备常用拼音缩写，例如 `ZF` 闸阀、`DF` 蝶阀、`ZHF` 止回阀、`JYF` 减压、`JZF` 截止、`YSD` 雨水斗、`XHS` 消火栓、`MDSS` 末端试水。带 `XT` 一类后缀时，往往是系统图版本。若每种缩写块的个数刚好等于系统分版的套数，说明它们只出现在系统图或图例里，平面没有布点，不计入平面工程量。阀门改按系统图和图集统计。这些缩写是命名习惯示例，不是某张图的块清单。

### ⚡ 洁具簇要先渲染，再决定是大样还是逐间平面

不要先入为主把洁具图层（例如 `FF-FIXT`）当成“一个卫生间大样”。沿街商铺一类图纸里，它可能是若干间铺面的真实一层平面，每间面积不同，带仓库和卫生间，洁具是逐间布置的。先渲染看清：是一个典型间，还是逐间平面。前者才用详图陷阱去乘房间数；后者直接计数，并先去掉系统分版副本。

### ⚡ 大量 AcDbProxyEntity：管长和平面渲染会失效

给排水图里可以有非常多的 `<AcDbProxyEntity>`，而且可能几乎都落在 `PIPE-*`、`J-*`、`VPIPE-*` 管线层和 `DIM_*` 标注层。它们是天正、鸿业等插件的自定义对象。DDC DwgExporter 通常一行一个代理，不展开缓存图形；这和 ODA File Converter 不是同一个程序。后果是管线长度量不到，`04_render.py` 只重绘块定义时平面几乎空白。被计数的消火栓、地漏、洁具如果是正常块引用，不受这一条影响。

可以试两条路，都依赖原图或已获授权的原插件，本仓库不能代替：

1. **天正在已获授权的前提下做“图形导出 → T3”。** 把天正对象炸成普通线、多段线和文字，再统计。转 T3 不可逆，先留原图副本。图形导出走通用解释时，不要求当前打开的模块和画图时的专业模块相同；例如用结构模块导出，给排水对象也可能被炸开。这只在本机天正能够完成导出时成立。导出后应看到代理变成普通实体；若代理还在，就还不能用量长脚本。
2. **`scripts/08_proxy_to_geom.py`。** 无天正时的 Python 后备。输入 DWG 时，ezdxf 的 odafc 插件会调用本机 ODA File Converter，许可见仓库根目录 [README.md](../../README.md)，不在这里重复。脚本再用 `proxy.virtual_entities()` 取缓存几何，按图层汇总图上长度或渲染。

成败关键是代理对象里必须有 proxy graphics（显示几何快照）：

- 原 DWG 保存时若 `PROXYGRAPHICS=0`，对象只存自定义数据，`virtual_entities()` 返回空。没有对应的天正 ARX，谁也解不出这些几何。
- 脚本会报 `[X] N 个代理对象无缓存几何`。这时只能回到已获授权的天正，用“文件布图 → 图形导出 → 天正 3（T3）”炸开，再统计。
- 先跑方法④。大量空代理说明这张图绕不开原插件；能吐出几何，才可以在没有天正的环境里算图上长度。设备、洁具等正常块引用仍然可以计数。

AutoCAD 或天正常以管理员身份运行。Windows UIPI 会挡住键鼠注入，COM 也可能要求提升权限。自动化驱动不了时，由持有授权的人手动导出，或改用非管理员身份启动。不要尝试绕过权限或授权。

### ⚡ 平面图上的“管长”经常不是管

给排水平面，尤其是商业铺面，常常只画干管、立管符号和短接头，完整走向在系统图（轴测或立管图）。只量平面会少算。

还要防另一类假长度：某个名字像 `J-其他` 的图层，渲染之后可能是“主要材料表”的表格框线，不是管。长度很大也不能加进管量，渲染可以一眼分开。

“主要材料表”是设计师汇总，优先查表。数量栏若写“按实际”或留空，图纸就没有给出管量，应写明需要按系统图和定额估算，不要编一个精确数。表里有用的常常是管径对照（例如给水 de20 对应 DN15 这类关系，以及 PVC-U 排水的常用外径）和规格，用来给已经数出的管件、立管配管径。对照关系以该图的表为准。

即便量到了线，也只是图上的平面水平投影，缺少立管竖向和管件余量，标成“估算，不是实测敷设量”。

### 管径和立管编号

- 管径看管线旁标注（DN15、DN100 等）。
- 管长在平面上多为代理实体或折线，几何常常量不到完整长度。按系统图回路和层高估算，并写明口径。
- 立管靠编号标注，不靠数图块。图例里常见“管道编号含义”一类说明，例如给水和消防用不同字母开头。以该图图例的定义为准。

### 优先查表和图集

图签常注“主要材料表、图例、选用标准图集目录”。阀门、管件、套管、洁具附件多引用国标图集（例如 09S304），平面不逐个画。不要在平面上硬数，按图集和系统图统计。洁具及配件安装表、管线规格对照若由设计师放在图里，优先采信。图层名可能是 `TWT_TAB` 或其他名字，以 `02_count` 的直方图为准。

## 建筑

> 先分清是新建还是既有建筑改造。两种图的权威来源不同。下面是通用情形，不是某一栋的实测记录。

- 可数对象：门、窗、楼梯、电梯、防火门、卷帘。新建项目的门窗常带编号块，编号形如 `M0922`、`C1512`、`FM乙1022`，这是编号格式示例。
- 新建项目里门窗表是权威来源：先读明细表的规格和数量，再用平面核对总数。门窗会在多张图里重复，用图框窗口去重。
- 防火门按甲、乙、丙级分开。

### ⚡ 立面改造经常没有门窗表

设计说明如果写的是改造、原有门窗拆除换新，就不要假设一定有门窗表。

- 先搜索文字里有没有“门窗表 / 数量 / 型号 / 洞口”。只有 `M01`、`M02` 这类字样时，它们可能是大样图号，不是门窗编号，也不能代替明细表。
- 门窗大样通常给类型，不给数量。一张大样里几种立面符号（平开窗、带亮子、铺面门窗）用来定型号。
- 立面上的窗可能是裸线：矩形加对角线或菱形，由 `LINE` 直接画成，不是按“一樘一个块”重复插入。块名若是无意义字符串，方法①和方法②都数不出窗。这时渲染立面后目视计数，并写明不确定度，不要写成精确总数。
- 改造图的尺寸可能没有 `DIMENSION` 实体，`msp.query("DIMENSION")` 可以是空的。尺寸只能在大样上按比例量，或向设计询问，两种都要标明是估算。
- 多栋图纸常按“楼栋分栏、竖向堆叠”排版：每栋一列，自上而下是做法表、平面、立面、门窗大样、节点。用标题文字（“一层平面图”“轴线立面图”“门窗大样图”）定位每张图的范围，再按 region 渲染。楼层数不同会让各列竖向错位。
- 立面装饰（涂料面积、线条长度、龙骨）归装修或按面积、长度另计；屋面钢结构归结构。不要塞进建筑门窗的个数。
- 交付时按“楼栋 × 立面 × 部位”说明计数口径。铺面门面可以按开间计。类型查大样。尺寸和精确总数做不到就写做不到。

### ⚡ 大图不要默认相信 odafc 自动转换

体积较大的建筑图上，曾经出现 `ezdxf.addons.odafc.readfile()` 转出的 DXF 缺少 `ENDSEC`、随后读不了的情况。这时改为直接调用本机已安装的 ODA File Converter 命令行，再用 `ezdxf.recover.readfile`。普通 `readfile` 也会因小的结构错误失败。命令参数含义是：输入目录、输出目录、版本、DXF、不递归、审核开关。不要把转换器路径写死在仓库或脚本里，用 `--oda` 或环境变量 `ODA_FILE_CONVERTER`。

图形界面可能异步写文件。调用返回后，等输出文件出现并且大小稳定再读。ODA 的许可见 [README.md](../../README.md)。

读入之后，要递归展开 `INSERT` 和 `ACAD_PROXY_ENTITY` 的 `virtual_entities()`，表格文字和平面几何才可能出现。它们经常在块定义或代理里，只遍历模型空间会得到空表。

### 文件辨识

图层里出现 `JZD`、`GXYZ`、`钻孔与剖线`、`河`、`GC*`（`GC` 常与鸿业相关）时，多半是管线定位或勘察总图，不是门窗平面。把它分到总图、给排水或勘察，不要当建筑平面去数门窗。文件名不能单独作为依据。

## 结构

> 钢框架、雨棚、连廊、临时钢架一类图纸，和电气、给排水的最大差别是几乎没有“设备图块”。主体是标注文字、构件编号和线或 polyline。算量从“数块”转到“读构件表，再量长度或算体积”。下面的规格都是格式示例。

- 可数或可量的对象：梁、柱、板、墙、洞口、预埋件。钢筋按配筋表。钢结构按截面表加构件长度估算重量。
- 构件表、配筋表、截面表、材料表优先，平面几何用来量长度和核对数量。
- 不要从平面上数钢筋根数来代替配筋表。

### ⚡ 块名直方图里多半是标注符号

`02_count` 看到的高频块，常常是尺寸箭头、标高、焊缝、钢筋点，而不是梁柱本身。常见符号块名示例：`_ArchTick`（尺寸箭头）、`_TSDBK`（标高）、`_WELD` 加序号（焊缝）、`点钢筋`。构件是几何线加文字编号。结构数量不靠 `02_count` 数这些符号，而靠截面表、文字编号（去重之后）和几何长度。无意义块名直接忽略。

### ⚡ 钢结构三段：截面表、编号计数、几何长度

1. **截面表**回答“是什么”。搜索“截面表 / 构件号 / 名称 / 截面 / 材质”。示例行（只说明表长什么样）：`GZ1 框架柱 方管□200×4 Q235B`，以及 `GL1` 框架梁、`GCL1` 次梁、`LT1` 檩条。以图上的表为准，不要套这个示例规格。
2. **构件编号文字**（`GZ1`、`GL1`、`GCL1`、`LT1`、`JC-1` 等）回答“有多少根”，但必须先去掉下面两类重复。
3. **几何长度**用来估算钢重：型材中线长度乘线密度。方管、矩管的截面积可以用外周和内周之差，再乘钢材密度（约 7850 kg/m³）。这是公式，不是过磅结果。公式数量级示例：方管 200×200×4 约 24.6 kg/m，矩管 100×50×3 约 6.8 kg/m。图上的截面不同就要重算。

### ⚡ 模型空间可能画了主图和缩略图两份

有的结构图在模型空间放两份：一份是带构件标注的主图，另一份是 key-plan 或标题栏附近的缩略图。把 `GL1`、`GCL1`、`LT1`、`JC-1` 等标注按 X（或按簇）分开，看编号是不是几乎都落在其中一簇。只数主图那一簇。这和给排水的系统分版不是同一种重复，去重思路一样：先聚类，再判断哪一簇是平面、哪一簇是缩略图或标题栏。

### ⚡ 立面布置图会把同一批构件再标一次

结构立面布置图会沿高度再标 `GL1`、`GZ1` 等，和平面是同一批构件的另一个视图，不能相加。立面标注的 Y 向跨度大，编号却和某张平面相同。数构件只认平面布置图、基础平面、柱脚锚栓布置图。立面、剖面和节点只用来取高度，不用来计数。

### ⚡ 柱数优先看柱脚锚栓布置图

平面里的柱常是小方块（方管截面，图层名可能是 `S-COLU`），有时画成同心双框。数几何时按中心点聚类，半径按该图比例选取，避免一柱拆成两块或两柱并成一块。多张平面都画柱时，柱脚锚栓布置图通常最干净：每柱一组锚栓和底板。`JC-1` 文字可能只标一部分，其余写“同 JC-1”，不要用文字个数当基础个数，改数基础方块。

### ⚡ 规则柱网用解析长度，再用几何交叉核对

规则框架可以先由柱中心聚类得到轴网（X 向各跨、Y 向排距），再算梁长：纵向梁根数乘棚长，横向梁根数乘排距。几何用来交叉核对。若梁层是双线轮廓，总长除以 2 才接近中线长度。檩条若是单线，按轴线长度和根数核算。柱长另算：柱数乘柱高，柱高从立面或标高读取。对不上时停下，不要取一个折中数当精确值。

### ⚡ 常见构件图层名

下列名字在天正或探索者一类图里出现过，只作过滤时的候选，以该图直方图为准：`S-COLU`（柱截面）、`S-COLU-DIMS`（柱定位）、`梁_主零件_实线` / `梁__实线` / `梁__虚线`、`柱_主零件_实线`、`Z中粗线`（檩条或次构件）、`S-AXIS`、`S-BEAM-KLTH`（梁或基础编号文字）、`S-DIMS` / `DIM`、`WELD_TEXT`、`梁截面名称`、`梁集中标注`。量长时按实际存放梁线、柱截面和檩条的图层过滤。

### ⚡ 精度要分开写

- 数量（柱、梁段、基础、预埋件个数）和型材截面、材质：截面表加去重计数，相对可靠。
- 构件长度和钢重：平面双线和解析长度可以互相核对，柱高、连接件、节点板、端部切割往往量不到。施工图阶段的钢重写明不确定度，精确值需要加工详图或深化图。不要写成过磅值。
- 混凝土（独立基础、短柱、地梁）：个数可以较可靠，体积常常不可靠。施工图可能不给基础尺寸表，截面只能从构造说明推断。体积标明“待详图核实”。
- 防火涂料和防腐按展开面积另列，不计入结构主材，但造价里常有这一项，说明中不要漏掉“未计”。

### 一般钢混结构

- 梁柱配筋按配筋表或平法标注（`KL` / `KZ` / `LL` 等编号）。钢筋量按构件长度乘配筋，不要数平面上的线。板钢筋按板配筋图的区域和间距。
- 预制过梁、构造柱、圈梁查预制构件表或标准图集，按门窗洞宽分型。
- 危大工程清单、绿色设计审查表是说明性表格，不是工程量，不要当材料表。

## 装修

> 装修图常自带“分部分项工程和单价措施项目清单与计价表”。它可能是最权威的已计量来源，但也可能只覆盖拆除，并且常以 OLE 或光栅存放，文字提取读不到表体。下面是这种图的读法，不是某一份清单的抄录。

- 可数对象：固定家具、活动家具、洁具、灯具、造型、门、窗、电梯、洁具五金。面积类：地面、墙面、天棚、新建隔墙、外立面涂料和线条。
- 装修图常和电气、给排水叠在同一底图上，先按图层过滤再数。
- 常见图层名示例：`FF-FIXT`（洁具）、`FF-FURN` / `FF-FURN-TY`（家具）、`DOOR` 或带“门”的图层、`WINDOW`、`BS-LIFT`（电梯，块名可能类似 `_liftd`）、`FC-FLOOR` / `FC-DD`（地面）、`RC-FIN` / `RC-LIGHT`（天花或灯具）、`DS-FINISH`、墙面造型、`WALL` / 原始墙 / 新建墙。电气图层可能同时存在。以直方图为准。

### ⚡ 先确认清单覆盖什么

清单与计价表若带项目编码、单位、工程量、综合单价和合价，合价应约等于工程量乘综合单价，可以用来自洽校验。

读的时候先看范围，再决定能不能照抄：

- 它可能只有拆除分部，措施项目（脚手架、垂直运输、大型机械）的工程量可能填 0，表示投标人自行考虑。
- 新建装饰（地面、墙面、天棚、隔墙、新门、家具、洁具）可能完全没有工程量。有清单不等于全专业都已计量。
- 拆除项的名称（棚顶、门窗、墙地面、吊顶等）有时能作为新做面积的近似基数，见下文。这是近似，不是实测。

不要在文档或成果里保留某一份真实清单的金额、项数或文件大小。

### ⚡ OLE 和光栅表：文字提取只有标题栏

清单或材料表的 DWG 里可能只有少量 `<AcDbOle2Frame>`（嵌入的表格对象）和标题栏文字，表体一个字都没有。对应 PDF 也可能只有标题栏在文字层里，表体是光栅。

处理顺序：

1. 先试文字层。若只有标题栏一类的少量词，表体就是光栅，必须渲染后再读。
2. 渲染使用调用者自己安装的工具。PyMuPDF 可以用，但任何脚本都没有 import 它，它也不是 MIT。官方同时提供 AGPL-3.0 和 Artifex 商业许可，见 [THIRD_PARTY.md](../../THIRD_PARTY.md)。下面只说明调用形状，不是本仓库的脚本，坐标请按那一页的实际分栏填写：


3. 行数多时，用 `scripts/09_ocr_table.py` 把 PNG 转成按坐标聚好的文字行，再用“工程量 × 综合单价 ≈ 合价”逐行复核。不要启用 PP-StructureV3 那一整套模型，除非你已经单独解决它的下载和依赖；基础 OCR 加按 y 聚行、按 x 排序通常够用。安装注意见 [tooling.md](tooling.md)。

### ⚡ 材料表常常只定材质，不定量

材料表按物料代号列材质。常见代号示例：`ST-` 石材、`CT-` 瓷砖、`PT-` 涂料、`WD-` 饰面板、`MT-` 金属、`GL-` 玻璃、`OL-` 其他（例如线条）。每行可能有规格、材质、燃烧性能和使用区域，但面积栏写“见图示 / 根据图纸 / 以实际选样为准”。这时材料表只作材质品种表，面积和数量回地面、墙面、天花材料图去量。和给排水材料表写“按实际”是同一类问题。

### ⚡ 多栋、多种平面可能叠在同一模型空间

平面布置、天花、地面材料、墙面材料、插座、原建筑、隔墙拆改，可能和强电、照明画在同一个模型空间里。`02_count` 的直方图是这些副本之和。

- 对洁具、门等插入点的 X 做大间隙聚类，会看到多簇平铺的平面，加上原点附近的图例块。先用标题文字框出**一张**平面布置图的范围，再数。
- 在完成这步之前，离散项只能标成“图面出现次数，多平面副本未去重”，精度写低。设计又没给量时，不要硬凑一个单栋精确数。
- 洁具、家具的块名经常没有意义，或是 `A$C` 后接十六进制的匿名块。用方法③渲染认型（台盆、坐便、蹲便、地漏等），不要靠块名猜。家具块若彼此几何都不同，就无法按型号归并，只能按立面或大样逐件看。
- 体量很大、在多张图里重复出现的填充或图元块，不是洁具或家具，不要计数。

### ⚡ 改造项目里，拆除面积只是新做面积的近似

内装改造常是拆了再做。拆除清单里的地面、内墙、天棚面积，可以作为对应新做面积的近似基数，比在平面上硬量填充更稳，而且有清单可核对。按材质细分（哪一种地砖各多少）仍然要回材料图分区。写成果时标明“由拆除项近似，不是实测净面积”。

### 装修的优先顺序

1. 找清单与计价表。有就逐项核对，并确认它是拆除清单还是全包清单。OLE 或光栅就渲染后读取，并用合价校验。
2. 材料表抄成材质品种表。面积栏若是“见图示”，不要把材质行当成数量。
3. 新建装饰：面积类用拆除面积作近似，再用材料图分区；门、洁具、家具按图层计数，多平面副本必须聚类或标明低精度。
4. 匿名块用方法③认型。外立面涂料和线条按立面量，并写明它不属于室内家具计数。

## 通用判断口诀

1. 先找明细表（门窗、配筋、材料、设备）。有表就以表为准，并先看表覆盖了什么。
2. 没有表，或数量栏写“详平面”，就渲染图例认符号，再按块名和图层数。
3. 数完必做：详图陷阱、图例陷阱、图框窗口去重；给排水再加系统分版去重。
4. 长度类（管、线、钢筋）能量几何就量，不能就写“估算”。示例和公式都不是实测值。
