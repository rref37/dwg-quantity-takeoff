# DWG 工程量取证统计 (三方取证法)

## 为什么需要它

DWG 是二进制图纸,设备/部件都以**图块(block reference)**为载体。算量的本质就是把图块按类型数清楚。难点有三个,本技能逐一破解:

1. **匿名块认不出**——动态块炸开/数组复制后块名变成 `A$C...`,连真实块名都读不出。
2. **图例/详图混进来**——图里除了真实平面,还并排画着图例表、典型房间大样、原始图/布置图副本,盲数会把这些算进去。
3. **多套图共用模型空间**——多栋/多层常画在同一模型里,无法按文件拆分。

算量最容易出错的不是"数不出",而是**数错了还以为对**。所以本技能强调取证(三个独立角度互相印证)和质检(详图陷阱、图例陷阱)。

## 流程与工具

> **装了 skill 跑不起来?先看 [`references/tooling.md`](references/tooling.md)**，列全外部依赖的用途、安装命令和常见问题。

全部脚本都读 **DXF**。DWG 由使用者自行安装的 ODA File Converter 转成 DXF，之后用 ezdxf 读取。本仓库不附带该程序，也不要求本机正在运行 AutoCAD。

```
python scripts/00_dwg_to_dxf.py "图纸.dwg" out_dxf            # DWG → DXF（第一步）
python scripts/02_count.py out_dxf/图纸.dxf                    # 之后各脚本读 DXF
```

ODA 程序的查找顺序：`--oda` 参数 → 环境变量 `ODA_FILE_CONVERTER` → PATH。下载页：https://www.opendesign.com/guestfiles/oda_file_converter

中文路径下请用 Python 脚本运行，不要用 `.ps1`（PowerShell 5.1 读含中文的脚本会乱码）。

## 脚本读取的字段

`scripts/_common.py` 的 `load()` 把 DXF 展开成每个实体一行的表。脚本通过下表的列名取数。完整定义见 `_common.py` 文件头。

| 列 | 含义 |
|---|---|
| `Description` | 实体类型：`<AcDbBlockReference>` `<AcDbText>` `<AcDbArc>` `<AcDbCircle>` `<AcDbLine>`… |
| `BlockTableRecord` | 块引用的**真实块名**（DXF 的 INSERT 名称）。不是"BlockReference"这类泛称 |
| `BlockId` | 实体属于哪个块定义（模型空间为空）。用它把块定义的几何聚起来 |
| `Layer` | 图层（各专业最可靠的分类依据） |
| `Position` `Center` `Radius` `StartPoint`/`EndPoint` `StartAngle`/`EndAngle` | 几何。坐标是 "x, y, z" 字符串，角度是弧度 |
| `ViewCenter` `ViewHeight` `Width` `Height` `Number` | 图框视口参数（去重/分栋用） |

## 三方取证法

### 方法① 数据直读 —— 能认名的部件
按 `BlockTableRecord`（真实块名）+ `Layer` 分组计数。大多数部件直接出数。
→ `scripts/02_count.py <dxf>`（可选 `--map 块名到类型.json`）

### 方法② 几何指纹匹配 —— 匿名块 `A$C...`
匿名块按其**几何组成**（各实体类型计数，如 `(Arc×16, Circle×1, Line×4)`）做"指纹"，相同指纹 = 同一符号。用已知命名块（从图例认得的）的指纹去匹配匿名块归类。无命名对应的，至少能确认"N 个同型"，再用方法③渲染成图让人认。
→ `scripts/03_fingerprint.py <dxf> --layers RC-LIGHT,... --known known.json`

### 方法③ 渲染对比 —— 定名 / 查图例 / 辨详图
**数据认不出时别死磕，把符号/图例渲染成图片看。** 从块定义的几何（line/arc/circle）按插入点平移重绘，叠加中文字（需要 `Microsoft YaHei` 字体才显示中文）。三种用法：
- 渲染**单个匿名块** → 看它长什么样（常一眼认出）；
- 渲染**图例区**（搜 "XX图例""图 例""名 称"等文字定位范围，把该区所有块按位置重绘）→ 得到权威的"符号↔名称"对照表；
- 渲染**可疑区域** → 判断那一簇到底是图例表还是典型房间大样。

→ `scripts/04_render.py <dxf> block <块名> -o out.png`
→ `scripts/04_render.py <dxf> legend <关键字> -o out.png`
→ `scripts/04_render.py <dxf> region x0 x1 y0 y1 -o out.png`
  负坐标直接写即可，例如 `region -2500000 -2000000 0 5000 -o area.png`。
  ⚠️ `04_render` 只重绘**块定义几何 + 文字**。给排水平面大量是 `AcDbProxyEntity`（天正/鸿业插件）和裸 polyline（墙/管），**不在块定义里，region 渲染平面几乎空白**。给排水靠图层计数 + 图例 + 局部商铺/大样渲染，别指望整张平面都渲得出来。

渲染完用图片人工判断，或拿给用户确认（用户认识图，一眼就能定型号）。

### 方法④ 代理对象几何提取 —— 天正/鸿业 AcDbProxyEntity（给排水必备）
天正等插件的管线/设备在 DXF 里只是一个 `ACAD_PROXY_ENTITY`，几何读不到（管长量不出、平面渲不出）。代理对象通常缓存了 proxy graphics（线/弧/字），可以取出来：`ezdxf` 的 `proxy.virtual_entities()` 展开，按图层汇总管长或渲染。
→ `scripts/08_proxy_to_geom.py <dxf 或 dwg> [--layers PIPE-给水,...] [--xlsx 管长.xlsx] [--render a.png --window x0 x1 y0 y1]`

⚠️ 若原图保存时没有存 proxy graphics，脚本会报"N 个空代理"，此时没有原插件解不出来。这种情况只能在天正里"图形导出→T3"炸开后再统计。详见 `references/disciplines.md` 给排水节。

## 去重与质检（不做必错）

### 图框窗口去重
图里常并排多套图 + 图例，原始块计数含重复。用图框视口的 `ViewCenter` + `ViewHeight` 框出真实平面区（用视口实体的值，别用 COM 的 Target，它常返回 (0,0)），只数窗内，排除图例和详图副本。
→ `scripts/05_viewport_windows.py <dxf> --layers EM-强电`

### 同层多副本去重（给排水尤甚）
比图框去重更隐蔽的一种重复：**同一层平面被复制成多张系统分版图**（给水图/排水图/消防图/喷淋图），每张是同一底图副本，只突出本系统。给排水**必做**，否则数量翻 2 到 4 倍。判定：按 X 坐标把块分成并排的"列/簇"，逐列统计各图层块数，**若两列逐图层数字几乎一致 = 互为副本，只取最完整一份计数**。详见 `references/disciplines.md` 给排水节。电气一般一层一图，没有这个问题。

### 详图陷阱（最易错，差几十倍！）
**先问：平面是"每个房间都画"还是"只画一个典型房间（详图）"？** 把某类部件的 X 坐标按开间宽分箱：
- 散布在 N 个开间（接近房间数） → 全平面布点，**总数即真实总数**；
- 只集中在 1 到 2 个开间 → 是详图，**真实总数 = 详图数 × 房间数**。

不验证这一步，数量可能差几十倍。→ `scripts/06_detail_check.py <dxf> --name <块名>`

### 图例陷阱
只出现在图例区（和"XX图例"文字、整齐表格在一起）、平面里没布点的部件 = **图例符号，实际安装 0 个**。用方法③渲染该区确认是图例表还是大样，别把图例当材料数。

### 多栋/多层共用模型 → 分栋做不到要诚实
若各栋/各层平面文件的图块直方图几乎相同（只差几个），说明共用同一模型空间，**无法按文件拆分**。分栋只能靠各专业的**系统图/总图**（逐栋不同）或图框视口范围；视口法常因多套副本叠加而拆不干净。**做不到就直说，给系统图规模 + 按比例估算**，别硬编数字。

## 各专业适配（方法通用，只换图层/块名）

工作流完全一样：先用方法③渲染该专业的**图例**拿到"符号↔名称"对照，再按 `BlockTableRecord` + `Layer` 数，最后窗口去重 + 详图/图例质检。各专业的图层命名习惯、优先权威来源见 `references/disciplines.md`：

- **电气**：`EM-强电/EM-弱电/EM-开关/EQUIP-安防/RC-LIGHT/EQUIP-箱柜` → 插座/开关/灯具/摄像头/配电箱
- **给排水**：管线/阀门/洁具/地漏/水表/管件（图层常为 `W-/D-/给水/排水`）；**管径靠标注文字，长度图上常没画线只能估**
- **建筑**：门/窗/楼梯/电梯。**门窗表（明细表）是权威来源，优先查表**再核平面
- **结构**：梁/柱/板/墙/钢筋。**构件表/配筋表优先**，平面多为标注
- **装修**：家具/洁具/灯具/造型/门窗。**清单与计价表（若已计量，逐项核对）+ 材料表/物料表优先**。清单常以 **OLE 嵌入对象**存放，DXF 读不出（只有图框标题栏），需要把对应 PDF 渲成图再逐行读（合价 ≈ 量 × 单价）。清单可能只含拆除，材料表写“见图示”的栏目只定材质不定量。PyMuPDF 是可选的外部库（AGPL 或商业许可），脚本不调用它。详见 `references/disciplines.md` 装修节

## 出表：用 xlsxwriter，别用 openpyxl

本类环境下 openpyxl 写 xlsx 常会崩（`Fill() takes no arguments`，连默认空表都崩）。统一用 `pd.ExcelWriter(engine="xlsxwriter")`。每项标**精确度**和**取证依据**；模糊的写区间加原因；**做不到的诚实标注**（如管线长度）。

→ `scripts/07_build_xlsx.py 输出.xlsx --csv 清单.csv`（CSV 列：序号,设备名称,规格,数量,精确度,取证依据）

## 算量边界（诚实）

数图块 = 数量统计，只是算量前半段。**导线/管线长度**：平面常只画符号不画连线，几何里量不到，只能按回路或标准估算，**不是实际敷设量，别包装成实测**。完整算量还需套定额。能精确的精确出来，模糊的标区间加原因，做不到的直说。这比给一堆假精确的数字有用得多。

## 典型工作顺序

1. `00_dwg_to_dxf.py` 把所有 DWG 转成 DXF。
2. 看每个文件的块/层直方图（`02_count.py` 不带 map），建立整体认识，并判断是否共用模型。
3. 方法③渲染图例，拿到"符号↔名称"对照（各专业第一步）。
4. 方法①按名字和图层数；方法②指纹收编匿名块；方法③给认不出的渲染定名。
5. 质检：详图陷阱（`06_detail_check.py`）、图例陷阱、窗口去重（`05_viewport_windows.py`）。
6. `07_build_xlsx.py` 出表，逐项标取证依据与精确度。

各脚本用法见 `--help`，外部依赖见 `references/tooling.md`。
